# ADR 0002: Training and evaluation data

**Status:** accepted, 2026-10-30

## Context

The fine-tuning data must have a license that allows training and redistribution of the result. It must cover single calls, several calls in one turn, and "no tool fits" cases. And it must not be generated by us with a frontier model: Anthropic's terms restrict using outputs to train competing models, and doing that would also make the comparison circular. Frontier models are used here only as baselines.

Candidates checked on 2026-10-30:

| Dataset | License | Access | Covers |
|:--|:--|:--|:--|
| `glaiveai/glaive-function-calling-v2` | Apache-2.0 | open | single calls, many "no tool" replies, ~1k distinct tools |
| `NousResearch/hermes-function-calling-v1` (`func-calling-singleturn`) | Apache-2.0 | open | parallel calls (2-11 per turn), ~2.6k tools |
| `Salesforce/xlam-function-calling-60k` | CC-BY-4.0 | gated (needs an HF login and accepting terms) | single and parallel calls |
| `Team-ACE/ToolACE` | Apache-2.0 | open | synthesized with GPT models |
| `gorilla-llm/Berkeley-Function-Calling-Leaderboard` | Apache-2.0 | open | benchmark with accepted-answer sets |

## Decision

- **Train, val and test:** glaive v2 plus hermes `func-calling-singleturn`, both Apache-2.0 and ungated. Each is pinned to a revision and SHA-256 in `data/manifest.json`.
- **External eval only:** a fixed 300-example BFCL v3 subset (60 each of simple, multiple, parallel, parallel_multiple, irrelevance). Its tools are also removed from train and val.
- **Not used:** xLAM, which needs a Hugging Face login this project doesn't assume, and ToolACE, whose provenance is GPT-generated.

## Consequences

- Both training sources are themselves synthetic, made by their authors with other models. The model card says so. We did not generate any data.
- glaive repeats a few hundred tools thousands of times and has only ~11k distinct first-turn queries. Dedup and a per-tool-set cap of 40 leave 6,353 train examples.
- hermes "no call" replies are mostly the model narrating a plan or asking for files it could have been handed, so they are dropped. Refusals come from glaive only.
- Reviewing 150 test examples (`data/handchecked_review.json`) showed real label noise: 22 of the 50 reviewed multi-call labels (all hermes) had to be dropped for invented values, invented structure or missing calls, and 5 of 40 glaive "no call" labels were wrong. The hand-checked set is the cleanest signal we have. Accuracy on the automatic test split partly measures agreement with the dataset's quirks.
